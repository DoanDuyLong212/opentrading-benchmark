## Common computation environment

Every source catalog now includes `analytics_compute`, equally for OT baseline, OT finance, OpenCode and DSH. It executes sum, mean, positive-base growth %, ordered margin fraction % and VND/million/billion scale using Decimal. Operands are `{call_id,path}` refs to successful source responses actually retrieved by the same per-trial MCP server process. No arbitrary numeric operands, task ID, gold, evaluator, selected hidden query, indicators/topN/profile capability or precomputed target values.

Original payloads/request contracts/golds/task graders and frozen v4.1/v3/common public validator are unchanged. Source replay still uses the original finite public requests. Derived ledger records use a distinct `deterministic_derivation` namespace, null upstream source/matched_entry ID, and an independently reproducible formula, values, input units, source response/payload hashes, selected scopes and original seven-field source receipts. Derived responses contain `source_evidence`, never forged upstream `benchmark_evidence`. Final answers must cite original source receipts; using the compute tool name as an upstream financial source is not specially rescued.

Validation rejects foreign/missing source IDs, bool/nonfinite/non-scalar values, noncanonical/negative array pointers, unknown or ambiguous units, monetary labels on unrelated volume/year fields, mixed aggregate periods/metrics, duplicate identical refs, incompatible ratio entity/metric/period scope, zero denominator, nonpositive growth base and results overflowing a finite JSON number. Margin semantics remain ordered numerator/denominator arithmetic; financial meaning/consolidation/requested-period coverage still require evaluator/manual audit. Growth callers choose current/previous order over distinct explicit periods; no hidden chronology or financial-metric classifier.

Offline five-bank fixture computes `160.9` sum and `32.18` mean from five original quote calls at `2026-10-30`, with all five ancestor receipts; no constants are in tool implementation. `ready_check.verify_mcp_attempt` reconstructs original source envelopes in ledger order and verifies actual derivations/dependency hashes, rejecting tampered results and derived receipts masquerading as upstream evidence. Common wire verification now includes the computation schema's constraints, alongside finite source schemas and identical public descriptions.
