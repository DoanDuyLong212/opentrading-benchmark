The current run cannot support a financial harness superiority claim, and the stateless smoke/pilot should not advance with these frozen tools. A benchmark-generated schema fails compilation in OT before source execution. No protected source, schema, protocol, grader or run artifact was modified, and no external model was called for this review.

`equivalent_schema()` in the frozen `tools/mcp_snapshot_server.py:87–89` applies Python `re.escape()` to literal punctuation and whitespace. This emits escapes valid in Python regex, including `\-` in crypto symbols/date strings and `\ ` in Vietnamese company names. OT's native `FinancePolicyState.validate()` (`finance-policy.ts:142–146`) compiles the complete preserved JSON Schema with AJV8.17.1. AJV defaults `unicodeRegExp:true` and constructs `new RegExp(pattern, "u")`. These identity escapes are invalid under JavaScript Unicode mode.

The captured DeepSeek OT-on request exposes the exact failing tool `mcp__opentrading__yf_commodities`; the first bad schema location is `/anyOf/0/properties/tickers/items/anyOf/6/pattern`, with pattern `^\s*[bB][tT][cC]\-[uU][sS][dD]\s*$`. It belongs to the BTC-USD sibling alternative. AJV compiles the whole schema, so a gold-only GC=F call also cannot get past schema compilation. Changing argument spelling or asking the model to repair fields cannot fix a malformed sibling schema.

`tiny-captured-repro.json` records the captured request SHA, exact pattern path, Bun1.4.4 proof that ordinary `new RegExp(pattern)` compiles while `new RegExp(pattern,"u")` throws, and the actual pinned SDK `safeValidateTypes(jsonSchema(..., FinancePolicyState.validate))` reproducing `AI_TypeValidationError` with the same SyntaxError as the trial. The original captured first arguments pass the unchanged Python JSON Schema validator. This is validator interoperability, not evidence that the model chose financially incorrect arguments.
